# 雙平台研習操作

## 找到現行工具

安裝後先讀此 skill 下 `references/repo-location.json` 的 `repoRoot`，再讀該位置的 `AGENTS.md` 與 `README.md`。直接從 repo 使用本技能時，repoRoot 是此資料夾上兩層。位置不存在時，依公開 repo <https://github.com/chianwu-hash/training-platform-workflow> 安裝並重新執行 `npm run skill:install`；不可沿用另一台電腦的絕對路徑。

依本次步驟讀 repo 的 `docs/SOP.md`：選課與登入讀第 1–3、5 節，影片監看讀第 4–5 節，問卷／測驗讀第 6–7 節，證書與回傳讀第 8–10、12 節。新電腦先讀 `docs/新電腦設定.md`；計時交接讀 `docs/AI接續提示.md`。完整規則由 repo 維護，不在安裝副本重複保存。

## 執行與接續

1. 核對本次帳號、研習需求、平台現況、課程通過標準與使用者最晚停止時間。登入由使用者完成；所有多帳戶網站寫入前核對可見完整身分。
2. 使用共享 `ai-browser-launch`，固定本次分配實例與精確分頁。沿用既有啟動器；缺少工具時按 README 安裝。每段操作前續約，工作 PID 登記、斷線與釋放由 repo 工具管理。忙碌只略過或等候。
3. 在 repo 工作目錄建立被 Git 忽略的 `local/course.json`，核對選中章節及播放器選擇器。以 `npm run training -- observe local/course.json` 建立現場基準；需要起點播放時才用 `start`。
4. 使用者要求計時或依序播放時，依其授權建立本機定時監看，先讀狀態與 nextCheckAt，到點用 `watch`；只有 `ready_to_advance` 時才用 `advance`，它會重新核對現場自然播完。不可讓排程與手動流程同時占用同一實例。例行喚醒安靜，必要處理、失敗或完成才通知；完成／停止／期限到須停用排程。
5. 工具出現 `stopped` 時停止操作並讀 SOP 判斷原因；不能只為繼續播放建立新狀態。使用者處理後，重新核對現場才接續。遇到普通閒置提示，只有本次明確授權才按 SOP 等待及點擊；不能把沉默當成本人在場。
6. 正式測驗與本人出席／簽到聲明交由使用者完成。一般問卷只依其指定偏好及送出授權處理。平台通過後下載原始證明，分別核對證書、時數傳報與學校回傳。

不快轉、改速、改學習時數、刷新規避提醒或製造活躍事件。設定、證書、登入資料及執行紀錄留在各電腦本機；不得提交到公開 repo。影片完成不代表課程通過或時數入帳。
